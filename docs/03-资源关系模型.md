# 资源关系模型

## 1. 目标

定义 Infrastructure Object 之间如何连接、查询和追踪，使 Atlas 能够表达数据中心拓扑和设备组成关系。

## 2. 关系结构

关系由以下内容组成：

- `source_object_id`
- `relationship_type_id`
- `target_object_id`
- `status`
- `created_at`

关系必须有明确方向，且源对象、目标对象均为 Infrastructure Object。

## 3. 第一阶段关系类型

| 类型 | 示例 | 含义 |
| --- | --- | --- |
| `contains` | Server → GPU | 对象包含子对象 |
| `installed_in` | Rack → Room | 对象安装于位置 |
| `connected_to` | NIC → Switch | 网络连接 |
| `feeds` | CDU → Rack | 冷却供给 |
| `powered_by` | Server → Power Shelf | 电力供给 |

## 4. 典型拓扑

```text
Data Center
  └── Room
      └── Rack
          └── Server
              ├── GPU
              └── NIC ──connected_to── Switch

CDU ──feeds── Rack
Power Shelf ──powered_by── Server
```

## 5. 关系规则

- 关系类型由统一字典管理。
- 不通过页面名称或临时字段表达关系。
- 关系创建、更新、失效必须记录历史。
- 部件更换应结束旧关系并建立新关系，不覆盖历史事实。
- 查询应支持对象的直接关系和拓扑路径。
- 关系权限必须受客户、组织、位置和 Management Scope 约束。
