# Atlas 资源关系模型设计

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.1 |
| 状态 | 核心模型设计文档 |

## 1. 文档目的

定义 Infrastructure Object 之间的关系模型、关系类型、生命周期、基础设施拓扑和 GB300 NVL72 关系示例。

## 2. 关系模型概述

Atlas 通过 Relationship 描述对象之间的连接：

```text
Object → Relationship → Object
```

例如 `Server contains GPU` 表示服务器包含 GPU。

AI 基础设施具有复杂层级关系。GB300 NVL72 可包含 Rack、Compute Tray、GPU、Grace CPU、NVSwitch、NIC、Power Shelf 和 CDU，不能只用 `server.gpu_count = 72` 等字段表达。

## 3. Relationship 核心模型

每条关系包括：

- Relationship ID
- Source Object
- Relation Type
- Target Object
- Attributes
- Status
- History

关系必须有明确方向，源对象和目标对象都必须是 Infrastructure Object。

## 4. 关系分类

- Containment Relationship：包含关系
- Physical Relationship：物理关系
- Logical Relationship：逻辑关系
- Operational Relationship：运维关系
- Dependency Relationship：依赖关系

## 5. 核心关系类型

### 5.1 `contains`

表示一个对象物理或逻辑上包含另一个对象：

```text
Rack contains Server
Server contains GPU
GB300 Rack contains Compute Tray
```

包含关系具有层级性和生命周期关联。删除父对象前必须检查其子对象。

### 5.2 `installed_in`

表示设备安装于某个物理位置：

```text
Server installed_in Rack-U32
GPU installed_in Compute Tray
```

### 5.3 位置关系

位置本身也是 Object，典型层级为：

```text
Data Center → Building → Room → Rack → U Position
```

位置通过 Relationship 表达，不能把完整路径复制到设备字段中。

### 5.4 `connected_to`

表示网络连接：

```text
BF3 Port1 connected_to SN2201 Port48
```

关系属性可包含 Port、Cable、Speed、Protocol 和 VLAN，例如 `Speed: 400G`、`Protocol: Ethernet`。

### 5.5 `feeds`

表示冷却资源向设备提供冷却：

```text
CDU feeds Rack
```

属性可包含 Flow Rate、Temperature、Loop 和 Pipe Connection。

### 5.6 `powered_by`

表示供电路径：

```text
Server powered_by Power Shelf
Power Shelf powered_by PDU
```

### 5.7 `depends_on`

表示资源依赖另一个资源：

```text
Server depends_on Network Switch
Server depends_on CDU
```

### 5.8 业务关系

业务对象也可以与 Infrastructure Object 建立关系：

```text
WorkOrder related_to GPU
ReplacementEvent affects GPU
```

## 6. 关系属性

每条关系可以包含：

### 创建信息

- Created Time
- Created By
- Source

### 状态

- Active
- Inactive
- Removed

### 可信度

客户提供的数据可标记为 `Medium`，自动发现的数据可标记为 `High`。可信度不能替代原始来源。

## 7. 关系生命周期

关系也需要保留历史。例如 GPU 从 Server-A 迁移到 Server-B：

```text
GPU-001 installed_in Server-A
        ↓ 2026-08 removed
GPU-001 installed_in Server-B
```

迁移不能覆盖原关系，必须记录移除时间、原因、操作者和新关系。

## 8. GB300 NVL72 关系示例

```text
Customer Data Center
  └── Rack
      └── GB300 Rack
          ├── Compute Tray
          │   ├── GPU × 8
          │   ├── Grace CPU
          │   └── BF3 NIC
          ├── NVSwitch Tray
          │   └── NVSwitch
          └── Power Shelf

CDU ──feeds── GB300 Rack
```

关系定义：

```text
Rack contains Compute Tray
Rack contains NVSwitch Tray
Rack contains Power Shelf
Compute Tray contains GPU
Compute Tray contains Grace CPU
Compute Tray contains BF3 NIC
BF3 NIC connected_to Network Switch
GPU connected_to NVSwitch
CDU feeds GB300 Rack
```

GPU 与 NVSwitch 的 NVLink 关系可使用专用关系类型，并记录 Bandwidth、Link Count 和 Status。

## 9. 关系查询能力

### 查询上游

查询 GPU 所属位置：

```text
GPU → Compute Tray → GB300 Rack → Rack → Data Center
```

### 查询下游

查询 CDU 影响的设备：

```text
CDU → Rack → Server → GPU
```

### 查询路径

查询网络路径：

```text
GPU → NIC → Switch → Storage Network
```

## 10. 设计原则

- 真实：关系必须符合物理世界。
- 可追踪：关系变化必须保留历史。
- 可扩展：支持新硬件和新连接方式。
- 不冗余：不要同时保存 `server.gpu_id` 和关系表中的同一事实。

## 11. 总结

Atlas 通过 Object、Relationship、Specification 和 History 构建 AI 数据中心的数字化拓扑。核心关系包括 `contains`、`installed_in`、`connected_to`、`feeds`、`powered_by`、`depends_on` 和 `related_to`。
