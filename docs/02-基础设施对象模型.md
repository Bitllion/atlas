# 基础设施对象模型

## 1. 目标

定义 Atlas 如何表达现实世界中的基础设施实体。所有设备必须先成为 `Infrastructure Object`，再被资产、运维、知识和自动化能力引用。

## 2. 核心概念

- `ObjectType`：对象类型，如 `SERVER`、`GPU`、`RACK`、`CDU`
- `Object`：具体实体，如 `SERVER001`、`GPU001`
- `Specification`：对象技术规格
- `Relationship`：对象之间的关系
- `History`：对象变化历史

Object 不等同于 Asset Record，也不等同于工单或其他业务记录。

## 3. 支持的对象类型

第一阶段至少支持：

`DATACENTER`、`ROOM`、`RACK`、`SERVER`、`GPU`、`NIC`、`CDU`、`POWER_SHELF`。

后续可扩展 CPU、Memory、Storage、Switch、Port、Link、Transceiver、PDU、UPS 等类型。

## 4. 对象通用属性

- `id`
- `object_type_id`
- `name`
- `serial_number`
- `manufacturer`
- `model`
- `status`
- `created_at`
- `updated_at`

对象状态必须可追踪，不能只覆盖当前值而丢失历史。

## 5. 规格模型

通用对象使用固定字段加扩展 JSON 属性表达差异化规格。示例：

```json
{
  "model": "B300",
  "memory": "288GB",
  "firmware": "97.xx",
  "pci_bdf": "41:00.0"
}
```

## 6. 业务约束

- 不为 GPU、Server、NIC 等单个设备创建重复的独立核心表。
- Asset、Operations、Knowledge 必须引用 Object。
- 对象可以位于自有机房、客户机房或第三方托管环境。
- 对象应支持 Ownership、Usage、Location、Maintenance Responsibility 和 Management Scope。
- 所有关键属性、状态、位置和关系变化必须进入 History。
