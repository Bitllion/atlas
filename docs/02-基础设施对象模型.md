## 1. 文档目的

本文档定义 Atlas 平台的基础设施对象模型（Infrastructure Object Model），主要描述：

- 什么是基础设施对象
- 对象生命周期
- 对象分类
- 对象属性模型
- 对象与资产的关系
- 对象与业务的关系

本文档是 Atlas Core 的核心设计文档，决定数据库、CMDB、资产关联、运维关联以及后续 AI 能力如何理解基础设施。

## 2. Infrastructure Object Model 概述

### 2.1 设计目标

Atlas 需要建立现实基础设施世界的数字化模型：

```text
数据中心
  ↓
机房
  ↓
机柜
  ↓
服务器
  ↓
GPU / CPU / NIC
  ↓
网络与冷却系统
```

Atlas 使用以下模型共同表达现实世界：

```text
Infrastructure Object + Relationship + Specification + History
```

### 2.2 为什么使用 Object 模型

传统资产系统按服务器表、GPU 表、交换机表分别建模，存在类型固定、扩展困难和复杂关系表达能力不足的问题。

例如 GB300 NVL72 可能包含 Compute Tray、GPU、Grace CPU、BF3 NIC、NVSwitch、Power Shelf 和 CDU。Atlas 不为每种新硬件不断增加核心表，而是使用统一的 Object、Object Type、Relationship 和 Specification 表达。

## 3. Object 定义

### 3.1 定义

`Infrastructure Object` 表示：

> 现实世界中具有独立身份、生命周期和管理价值的基础设施实体。

### 3.2 对象分类

#### IT Resource

- Server
- GPU Server
- GPU
- CPU
- Memory
- Storage
- NIC

#### Network Resource

- Switch
- Port
- Link
- Transceiver

#### Facility Resource

- Data Center
- Room
- Rack
- CDU
- Cooling System

#### Power Resource

- PDU
- UPS
- Power Shelf
- Power Module
- PSU

对象类型由 `ObjectType` 统一管理，第一阶段至少初始化：`DATACENTER`、`ROOM`、`RACK`、`SERVER`、`GPU`、`NIC`、`CDU`、`POWER_SHELF`。

## 4. Object 核心属性

所有 Object 具有以下通用维度：

```text
Object
├── Identity
├── Classification
├── Location
├── Ownership
├── Management Scope
├── Status
├── Specification
└── History
```

### 4.1 Identity：身份

- Object ID：Atlas 内部唯一标识
- Name：对象名称
- Serial Number：设备厂商序列号
- Asset Number：企业内部资产编号
- UUID：设备或部件唯一标识

Serial Number 和 Asset Number 不可混为一谈；Object ID 也不能被资产编号替代。

### 4.2 Classification：分类

通过 Object Type 管理对象类型，例如 `SERVER`、`GPU`、`NIC`、`CDU`、`RACK`。

### 4.3 Location：位置

位置本身也是 Object。典型位置层级为：

```text
Data Center → Room → Rack → Device
```

位置关系通过 Relationship 表达，而不是把完整位置路径复制到设备字段中。

### 4.4 Ownership：所有权

建议支持：

- `OWNED`
- `CUSTOMER_OWNED`
- `THIRD_PARTY`

所有权不等于部署位置。例如，资产可以属于 Atlas 公司，但部署在客户数据中心。

### 4.5 Management Scope：管理范围

Management Scope 描述 Atlas 可以管理对象的范围：

- `FULL_CONTROL`
- `HARDWARE_ONLY`
- `MAINTENANCE_ONLY`
- `NO_ACCESS`

客户租赁设备示例：

```yaml
Ownership: OWNED
Location: CUSTOMER_SITE
Management: HARDWARE_ONLY
```

### 4.6 Status：状态

对象通用生命周期状态：

- `PLANNED`
- `ACTIVE`
- `INACTIVE`
- `MAINTENANCE`
- `RETIRED`

资产域和运维域可以在此基础上提供业务状态，例如采购中、库存、使用中、故障和维修中。状态变化必须进入 History。

## 5. Object Specification 模型

### 5.1 设计原则

Object 描述“它是谁”，Specification 描述“它有什么能力”。通用字段与类型扩展字段分离，推荐使用固定字段加 JSONB 扩展属性。

GPU 示例：

```yaml
Object: GPU-B300-001
Specification:
  Model: B300
  Memory: 288GB
  Firmware: 97.xx
  UUID: xxxx
  PCI BDF: 0000:41:00.0
```

### 5.2 规格分类

通用规格：

- Manufacturer
- Model
- Serial
- Firmware

GPU 规格：

- HBM Capacity
- CUDA Core
- NVLink
- UUID
- PCI BDF

NIC 规格：

- MAC
- Firmware
- Speed
- Port
- PCI BDF

CDU 规格：

- Cooling Capacity
- Flow Rate
- Temperature
- Pump Status

## 6. Object Relationship 模型

对象之间通过统一 Relationship 连接。典型关系包括：

```text
Rack ──contains──────> Server
Server ──contains────> GPU
Device ──installed_in─> Rack
NIC ──connected_to───> Switch
CDU ──feeds──────────> Rack
Power Shelf ──powered_by──> Server
```

复杂关系的完整定义见 `docs/03-资源关系模型.md`。

## 7. Object 与业务域关系

Infrastructure Object 是所有业务的统一基础：

```text
Object ──> Asset Record
Object ──> Work Order
Object ──> Knowledge / Document / Experience
```

- Asset Record 表示采购、编号、供应商和维保等资产信息。
- Work Order 表示故障、维修、巡检和变更等过程。
- Knowledge 表示文档、SOP、故障案例和维修经验。

三类记录不能混为一谈，但都必须能够引用 Object。

## 8. Object 生命周期

```text
Created
  ↓
Discovered
  ↓
Active
  ↓
Changed
  ↓
Maintenance
  ↓
Retired
```

对象生命周期应支持：

- 初始创建
- 自动发现或人工登记
- 部署和位置变化
- 部件更换
- 维修和状态变化
- 退役和历史查询

## 9. 数据来源模型

Object 数据可能来自：

- Discovery
- Manual
- Import
- Document
- Customer Report
- Vendor

每次重要数据变化需要记录：

- Value
- Source
- Timestamp
- Operator
- Update Status
- Confidence

客户环境无法持续采集时，客户报告、文档或人工录入仍然可以维护对象和资产生命周期。

## 10. GB300 NVL72 示例

```text
Data Center
  └── Room
      └── Rack-001
          └── GB300 Rack
              ├── Compute Tray 01
              │   ├── GPU
              │   ├── CPU
              │   └── NIC
              └── NVSwitch Tray
                  └── NVSwitch
```

GPU 对象示例：

```yaml
Object: GPU-B300-001
Type: GPU
Specification:
  Model: B300
  Firmware: 97.xx
  UUID: xxxx
  PCI BDF: 41:00.0
Relationship:
  belongs_to: Compute Tray
```

## 11. 设计原则总结

Object Model 必须满足：

- 可扩展：支持新硬件、新厂商和新资源类型
- 可追踪：支持历史变化和数据来源
- 可关联：支持物理、网络和业务关系
- 可运营：支持资产、运维和知识管理

所有后续业务能力，包括 Asset、Operations、Knowledge 和 Automation，都必须基于 Object、Relationship、Specification、Data Source 和 History 构建。
