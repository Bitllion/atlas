# 属性与采集模型

## 1. 目标

统一管理基础设施对象的技术属性、数据来源、更新时间和可信度，不假设所有设备都能实时采集。

## 2. 属性模型

对象属性分为：

- 固定字段：名称、序列号、厂商、型号、状态
- 类型规格：GPU 显存、NIC MAC、CDU 流量等
- 扩展字段：设备厂商特有属性
- 派生属性：根据关系或历史计算的属性

扩展属性优先使用 JSONB 或等价结构，避免为单个设备创建专用表。

## 3. 数据来源

- Discovery：Redfish、IPMI、SNMP 等自动发现
- Import：文件导入
- Vendor Data：厂商资料
- Customer Data：客户报告或客户 API
- Manual Input：人工录入

## 4. 数据元信息

每条重要数据至少应关联：

- 来源类型
- 来源标识
- 采集或录入时间
- 最近更新时间
- 更新状态
- 可信度
- Access Capability

示例：

```yaml
source:
  type: CUSTOMER_REPORT
  access: NO_DIRECT_ACCESS
  update_frequency: MONTHLY
```

## 5. 采集约束

- 自动采集失败不能删除对象。
- 客户环境可能只有月度报告或人工反馈。
- 采集任务必须可重试、可恢复，并记录失败原因。
- 采集数据不能绕过权限模型直接修改受限设备。
- 新数据应通过 History 保留变化记录。
