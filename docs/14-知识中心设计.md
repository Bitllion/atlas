# 知识中心设计

## 1. 目标

沉淀基础设施相关知识，使文档、SOP、故障案例和维修经验能够直接服务于对象和运维活动。

## 2. 知识类型

- 厂商文档
- 技术手册
- SOP
- 故障案例
- 维修经验
- 客户交付资料

## 3. 知识关联

知识应能够关联：

- Infrastructure Object
- Object Type
- Specification 或 Firmware 版本
- History
- Operations Record
- Customer/Site

## 4. 生命周期

```text
创建 → 审核 → 发布 → 版本更新 → 归档
```

知识版本不能覆盖旧内容，重要技术结论应可追溯来源和适用范围。

## 5. 权限

客户资料、厂商资料和内部经验必须遵循租户、组织、客户和文档级权限控制。
