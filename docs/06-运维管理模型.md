# 运维管理模型

## 1. 目标

管理基础设施运行、故障、巡检、维修和变更过程，确保所有运维行为可追踪。

## 2. 运维记录

主要业务记录包括：

- 故障工单
- 维修工单
- 巡检工单
- 变更工单
- 部件更换记录
- 现场服务记录
- 固件升级记录

运维记录不是 Object，但必须关联一个或多个 Object，必要时关联 Rack、Server、GPU 等上下文对象。

## 3. 工单生命周期

```text
创建 → 分派 → 处理中 → 待验证 → 已关闭
```

异常场景应支持挂起、转派、重新打开和取消，并保留操作历史。

## 4. 权限与环境

内部环境可能通过采集发现故障；客户环境可能由客户报告故障，再安排工程师现场处理。两者都属于 Operations。

运维流程必须根据：

- 设备位置
- Management Scope
- 网络环境
- 客户授权

判断能否 SSH、执行命令、修改配置或仅允许硬件更换。

## 5. 状态管理

基础状态至少包括：

- 正常
- 故障
- 维修中
- 退役

状态变化必须写入 History，并记录操作者、来源和时间。
