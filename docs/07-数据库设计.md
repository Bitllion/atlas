# 数据库设计

## 1. 设计目标

使用 PostgreSQL 建立可扩展的 Infrastructure Core，支持对象、关系、规格、来源、历史和多客户隔离。

## 2. 核心表

第一阶段至少包含：

- `object_types`
- `objects`
- `object_specs`
- `relationship_types`
- `relationships`
- `object_history`

后续扩展资产、租户、工单、知识和权限相关表。

## 3. 关键约束

- `objects.object_type_id` 引用 `object_types`。
- `object_specs.object_id` 引用 `objects`。
- `relationships` 的源对象和目标对象均引用 `objects`。
- 删除对象前必须处理关系、业务记录和历史记录。
- JSONB 用于可变规格，不用于替代核心关系。
- 时间字段统一使用带时区时间。
- 数据库结构通过 Alembic 迁移管理。

## 4. 历史与审计

对象状态、属性、关系、位置和维保变化必须保留 before/after 数据、操作人、来源和时间。历史记录不可因更新当前值而丢失。

## 5. 扩展方向

数据库应预留 `tenant`、`organization`、`site`、`management_scope`、`data_source` 等维度，但不为单页面需求添加临时结构。
